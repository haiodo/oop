## Задача 5. Упрощенный парсер CSV

### Subtask #1 — печать std::tuple

Используя рекурсивные шаблоны реализовать оператор вывода для std::tuple как свободную функцию (в глобальном пространстве имен), объявленную в подключаемом заголовке:

```c++
// формат вывода: (e0, e1, e2, ...)
template <typename Ch, typename Tr, typename... Args>
std::basic_ostream<Ch, Tr>& operator<<(std::basic_ostream<Ch, Tr>& os,
                                       std::tuple<Args...> const& t);
```

Требования:

- Реализовать через рекурсивные шаблоны (или `index_sequence` - допустимо).
- Не модифицировать `namespace std`.
- Примеры:
  - `std::tuple<int, std::string>{42, "foo"}` -> `(42, foo)`
  - `std::tuple<int>{7}` -> `(7)`
  - `std::tuple<>{}` -> `()`
- Оператор объявлен в глобальном пространстве имён, а аргумент - `std::tuple`. ADL искать его
  не будет: поиск пойдёт в `namespace std`. Работать это будет только благодаря обычному поиску
  по области видимости, и **только если заголовок подключён до точки вызова**.
  Отсюда следствие, которое надо проверить тестом: вывод вложенного кортежа
  (`std::tuple<int, std::tuple<int, int>>`) должен работать. Если у вас рекурсия печати ищет
  оператор через ADL - не заработает.

### Subtask #2 — простой CSV-парсер

#### Формат

- Строки разделяются символом '\n'.
- Колонки разделяются символом ','.
- Ни ',' ни '\n' не встречаются внутри данных (без экранирования).
- Количество колонок в строке должно совпадать с количеством типов.

#### CSVParser

Нужно написать шаблонный класс CSVParser<Ts...>, позволяющий лениво итерироваться по строкам CSV и получать std::tuple<Ts...>.

Минимальный интерфейс:

- Конструктор: CSVParser(std::istream& in, std::size_t skip_rows = 0);
- Итерация: begin()/end() со стандартным InputIterator (см. cppreference: InputIterator).
- Итератор:
  - value_type = std::tuple<Ts...>
  - iterator_category = std::input_iterator_tag
  - Инкремент читает следующую строку по требованию (lazy).

Преобразование типов:

- Для каждого поля применяется `operator>>` в соответствующий тип `T`.
- Для `std::string` поле берётся **как есть**, целиком, вместе с пробелами.
  `operator>>` для `std::string` останавливается на первом пробеле, поэтому применять его к строковому
  полю нельзя: поле `"John Smith"` превратилось бы в `John`. Для `std::string` нужна отдельная ветка.
- Поле должно быть **прочитано целиком**. `std::istringstream("12abc") >> i` вернёт `12` и не выставит
  `failbit` - остаток молча потеряется. После извлечения требуется проверить и `fail()`, и то,
  что поток дошёл до конца поля (`eof()` либо `peek() == EOF`). Иначе `12abc` разберётся как `12`,
  а `1.5` для `int` - как `1`, и тесты этого не заметят.
- Несовпадение количества полей или ошибка парсинга -> исключение `std::runtime_error` с кратким описанием.

Граничные случаи (определены явно, реализовать все):

- Последняя строка **без** завершающего `\n` - валидная строка, читается наравне с остальными.
- Пустой поток - `begin() == end()`, цикл не выполняется ни разу, исключений нет.
- Завершающий `\n` в конце файла пустой строки после себя **не создаёт**.
- Пустое поле (`1,,x`) - ошибка преобразования для арифметических типов, пустая строка для `std::string`.
- `skip_rows` больше числа строк в потоке - не ошибка, итерация пуста.
- Строка из одного поля при одном типе в `Ts...` - валидна.
- `CSVParser<>` без типов - разрешать не требуется, но и падать не должно: зафиксируйте выбор.

Пример:

```c++
int main() {
    std::ifstream file("test.csv");
    CSVParser<int, std::string> parser(file, 0);
    for (auto const& row : parser) {
        std::cout << row << std::endl; // row: std::tuple<int, std::string>
    }
}
```

### Subtask #3 — улучшенный CSV-парсер

Добавить:

1. Экранирование данных (кавычки).
   - По умолчанию quote = '"'.
   - Внутри "...", разделители колонок и пробелы — это данные, а не разделители.
   - Внутри кавычек последовательность "" интерпретируется как один символ ".
   - Переносы строк внутри кавычек по умолчанию не поддерживаются (упрощение).
2. Конфигурацию парсера:
   - Символ разделителя строк: row_delim (по умолчанию '\n').
   - Символ разделителя колонок: col_delim (по умолчанию ',').
   - Символ экранирования: quote (по умолчанию '"'; можно отключить, например, quote = '\0').
   - Конструктор: CSVParser(std::istream& in, std::size_t skip_rows,
     char row_delim, char col_delim, char quote = '"');
3. Улучшенную обработку ошибок:
   - Бросать исключение `CSVParseError` с полями: `line` (1-based, номер строки в исходном потоке,
     включая пропущенные через `skip_rows`), `column` (1-based, номер **символа** в строке), `message`.
   - `CSVParseError` **наследуется от `std::runtime_error`**. Это обязательно: тесты из Subtask #2,
     ловящие `std::runtime_error`, должны продолжать работать без правок после перехода к Subtask #3.
   - `what()` возвращает строку, содержащую номер строки, номер колонки и описание.
   - Ошибки: незакрытая кавычка, неожиданный конец строки, лишние/недостающие колонки, ошибка преобразования типа.
   - `column` при несовпадении числа полей: если полей **меньше** ожидаемого - позиция
     сразу за концом строки (`длина строки + 1`); если **больше** - позиция первого лишнего поля.
   - Уточнение по кавычкам: кавычка допустима только в начале поля. Символ `"` в середине
     незакавыченного поля - ошибка. Символы после закрывающей кавычки до разделителя - ошибка.

Примеры:

```c++
std::istringstream in("id;name\n1;\"Doe, John\"\n2;\"Alice \"\"The Ace\"\"\"");
CSVParser<int, std::string> p(in, /*skip*/1, /*row*/'\n', /*col*/';', /*quote*/'"');
for (auto const& row : p) std::cout << row << "\n";
```

### Замечания по реализации

- Итератор относится к категории **InputIterator** - однопроходный. Термин "однонаправленный"
  в русской литературе обычно означает ForwardIterator (многопроходный) - это не тот случай.
  Следствия, которые надо осознать и отразить в коде:
  - После `++it` все ранее полученные копии итератора становятся недействительными.
    Второй проход по тому же `CSVParser` невозможен - `begin()` дважды вызывать нельзя.
  - `it++` (постфиксный) для InputIterator **не обязан** возвращать копию итератора.
    Возвращать `iterator` по значению здесь неправильно: копия указывала бы на уже прочитанное состояние.
    Верните `void` или прокси-объект, хранящий значение.
  - Все итераторы, дошедшие до конца, равны `end()`. Два ещё не дошедших итератора
    считаются равными между собой - как у `std::istream_iterator`. Осмысленное сравнение
    здесь только одно: `it != end()`.
- Храните минимум состояния: ссылка на поток, текущее разобранное значение, номер строки, флаг конца.
- Ленивая загрузка: чтение и разбор следующей записи происходит при `++it`.
  Первая запись читается при вызове `begin()`.
- Конец итерации - достижение EOF при отсутствии непрочитанных данных.
- Копирование и разрушение итератора не должны бросать исключений (пометьте копирующий конструктор
  и деструктор `noexcept`, если тип значения это позволяет). Само чтение строки исключения бросать может.

### Технические требования

1. Проект собирается шаблоном курса: [oop-cpp-template](https://github.com/haiodo/oop-cpp-template).
   Задача целиком шаблонная, поэтому весь код будет в заголовках. При этом `SOURCES`
   в `oop_task()` не может быть пустым: заведите файл `csv_parser.cpp`, который просто
   подключает оба заголовка. Он заодно проверяет, что заголовки самодостаточны
   и собираются сами по себе.
2. Тесты на GoogleTest:
   - Печать tuple: пустой, 1 элемент, несколько элементов, строки со спецсимволами.
   - Простой CSV: корректный парсинг, неверное число колонок, ошибка типа.
   - Улучшенный CSV: кавычки, удвоенные кавычки, пользовательские разделители.
   - Проверка координат в CSVParseError (line/column).

- [ ] Работает для вложенного кортежа.

Базовый парсер:

- [ ] Ленивое чтение: следующая строка разбирается по требованию, а не вся сразу.
- [ ] `value_type` и `iterator_category` заданы корректно.
- [ ] Постфиксный `operator++` не возвращает копию итератора, указывающую
      на уже прочитанное состояние.
- [ ] Для `std::string` поле берётся целиком, вместе с пробелами.
- [ ] Поле читается полностью: `12abc` для типа `int` - ошибка, а не молчаливое `12`.
- [ ] Последняя строка без завершающего `\n` читается наравне с остальными.
- [ ] Завершающий `\n` не порождает лишнюю пустую строку.
- [ ] Пустой поток: `begin() == end()`, исключений нет.
- [ ] `skip_rows` больше числа строк - не ошибка, итерация пуста.

Расширенный парсер:

- [ ] Кавычки: разделители и пробелы внутри них - данные.
- [ ] Удвоенная кавычка внутри поля даёт один символ `"`.

- [ ] `CSVParseError` наследуется от `std::runtime_error`.
- [ ] `line` и `column` указывают на реальное место ошибки, `what()` их содержит.

- [ ] Позитивные: пустой поток, одна строка без `\n`, `skip_rows` во всех вариантах,
      строковое поле с пробелами, запятая внутри кавычек, удвоенные кавычки,
      пользовательские разделители, отключённые кавычки, вложенный кортеж.

      `"unclosed`; `"abc"def`; `ab"cd`.
