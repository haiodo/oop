## Задача 4. Sound Processor

Написать программу, которая получает на вход один или несколько звуковых файлов формата WAV и текстовый файл с описанием преобразований. Программа последовательно применяет конвертеры к звуковому потоку и сохраняет результат в выходной WAV-файл.

Запуск программы:

```
sound_processor -c <config.txt> <output.wav> <input1.wav> [<input2.wav> ...]
sound_processor -h | --help
```

- Ключ -h/--help несовместим с -c.
- При -c параметры обязательны: файл конфигурации, выходной файл, хотя бы один входной файл.

WAV-файл содержит заголовок и данные — последовательность сэмплов (амплитуда сигнала во времени). Частота — сэмплов в секунду. Последовательность сэмплов далее называется потоком (не путать с потоками ввода/вывода).

### Поддерживаемый формат WAV (вход и выход)

- Контейнер RIFF/WAVE.
- Подчинённый chunk fmt:
  - AudioFormat = 1 (PCM, без кодирования).
  - NumChannels = 1 (моно).
  - SampleRate = 44100 Гц.
  - BitsPerSample = 16 (signed, little-endian).
  - BlockAlign, ByteRate соответствуют вышеуказанным параметрам.
- Chunk data присутствует и согласован по размеру.
- Семпл - целое int16 в диапазоне [-32768, 32767], тишина - 0.
- При записи результата достаточно минимально необходимого корректного заголовка (RIFF, fmt, data) с правильными размерами.

**Важно: чтение чанков.** WAV - это контейнер RIFF, а не файл с фиксированным 44-байтным заголовком.
Между `fmt ` и `data` могут стоять посторонние чанки (`LIST`, `fact`, `JUNK`, `bext`), и ffmpeg
без ключа `-bitexact` их пишет. Требуется:

- разбирать файл как последовательность чанков: 4 байта идентификатора, 4 байта размера (uint32 LE), данные;
- **неизвестные чанки пропускать** по их размеру, а не падать и не считать их данными;
- учесть выравнивание: если размер чанка нечётный, за данными следует один байт-заполнитель,
  который в размер не входит;
- размер `data` брать из его собственного заголовка, а не "всё до конца файла".

Решение, читающее первые 44 байта и считающее остаток данными, на реальных файлах даст мусор
на входе и тишину или шум на выходе. Проверьте на файле, сконвертированном ffmpeg **без** `-bitexact`.

Значения `sampleRate` и `bitsPerSample` берутся из чанка `fmt `, а не подставляются константами.
Если они не равны 44100/16 или каналов не 1 - это ошибка `UnsupportedFormatError`, а не повод
интерпретировать данные как 44100.

Для конвертации из другого формата в нужный можно использовать ffmpeg:

```
ffmpeg -i input.any -f wav -bitexact -acodec pcm_s16le -ar 44100 -ac 1 output_mono_16bit.wav
```

### Конвертеры

Конвертер — компонент, принимающий на вход один или несколько потоков (основной + дополнительные) и выдающий один выходной поток. Конвертер имеет параметры.

Обязательные конвертеры:

1. Заглушить интервал (mute)

- Смысл: занулить (сделать тишину) в указанном интервале времени.
- Параметры: start end (секунды, вещественные числа).
- Поведение:
  - Интервал понимается как [start, end), т.е. end не включительно.
  - Индекс семпла `s(t) = round(t * sampleRate)`.
  - Выход имеет ту же длину, что и вход.
  - Если интервал выходит за пределы, он обрезается по границам потока.
  - Если start >= end — изменений нет.

2. Миксер (mix)

- Смысл: примиксовать дополнительный поток к основному, начиная с позиции offset.
- Параметры: $n offset, где $n — ссылка на дополнительный входной файл, offset — секунды (вещественное, по умолчанию 0, если опущен).
- Поведение:
  - Длина выхода = длина основного входного потока.
  - Для каждой позиции i (семпл):
    - Если соответствующий семпл из дополнительного потока существует (учитывая смещение), выходной семпл — среднее двух значений.
    - Иначе — семпл основного потока.
  - Формула (для перекрывающейся области):
    - `y[i] = (x0[i] + x1[i - offsetSamples]) / 2`
  - `offsetSamples = round(offset * sampleRate)`.
  - Если дополнительный поток длиннее - лишняя часть игнорируется; если короче - за его пределами берётся основной поток без изменений.
  - Насыщения (clamp) здесь **не требуется**: среднее двух значений `int16` всегда лежит в диапазоне `int16`.
    Требуется другое - **не переполнить промежуточную сумму**. `x0[i] + x1[j]` в типе `int16_t`
    переполняется (signed overflow - UB, ловится UBSan); складывать надо в `int32_t`.
    Это единственное место в задаче, где `clamp` был бы лишним кодом, а промежуточное расширение типа - обязательно.
  - Округление при делении на 2 задайте сами (усечение к нулю либо к минус бесконечности) и зафиксируйте
    в документации: тесты должны проверять именно вашу версию на отрицательных значениях,
    где `-3 / 2` и `floor(-3 / 2)` дают разный результат.

3. Третий конвертер на ваш выбор

- Требование: должен давать слышимый эффект, иметь минимум 1 параметр и быть **потоковым** -
  см. ограничение на память ниже.
- Пример: усиление (gain)
  - Смысл: умножить амплитуду на коэффициент.
  - Параметры: factor (вещественное), например 0.5, 1.5, 2.0.
  - Формула: `y[i] = clamp16( round( x[i] * factor ) )`. Здесь clamp обязателен: при factor > 1
    результат легко выходит за `int16`.
- Можно реализовать другой (echo, tremolo, fade in/out, distortion и т.п.), параметры задокументировать в справке.
- **Нельзя `reverse`.** Разворот потока требует удержать в памяти весь сигнал целиком, что прямо
  противоречит требованию "память не зависит от длины потоков". Любой конвертер, которому нужен
  доступ к концу потока до того, как выдан его первый семпл, по этой же причине не подходит.
  Конвертер с ограниченной задержкой (echo с фиксированной линией задержки) - подходит,
  и в `REPORT.md` надо указать, сколько памяти он требует.

Разрешены дополнительные конвертеры и/или параметры на усмотрение автора. Все доступные конвертеры и их синтаксис должны автоматически появляться в справке (-h).

### Конфигурация (файл config.txt)

- Формат: по одному конвертеру на строку.
- Строки, начинающиеся с #, — комментарии; пустые строки допускаются.
- Токены разделяются пробелами/табами.
- Типы аргументов:
  - Целые (например, 10), вещественные (например, 2.5) — секунды и коэффициенты.
  - Ссылка на поток: $n, где n — номер входного файла, начиная с 1. $1 — это input1.wav, $2 — input2.wav, и т.д.
- Если конвертер требует дополнительный поток (например, mix), он получает его отдельную копию с начала файла. Один и тот же входной файл можно использовать многократно.
- Ошибки конфигурации:
  - Неизвестный конвертер.
  - Неверное число/тип аргументов.
  - Ссылка $n вне диапазона доступных входных файлов.
  - Лишние токены в строке.

Пример:

```
# заглушить первые 30 секунд input1
mute 0 30

# смиксовать с input2, начиная с 10-й секунды
mix $2 10

# заглушить 3-ю минуту (120..180) в уже обработанном потоке
mute 120 180

# увеличить громкость в 1.5 раза
gain 1.5
```

### Правила исполнения

1. Конвертеры применяются последовательно в порядке строк конфигурации.
2. Первый конвертер получает основной входной поток (input1). Результат предыдущего - вход для следующего.
3. Выход последнего конвертера сохраняется в указанный output.wav.
4. Пустой конфиг (только комментарии и пустые строки) - не ошибка: output.wav становится копией input1
   с корректно перезаписанным заголовком.
5. Все времена - в секундах, перевод к индексам семплов: `round(t * sampleRate)`, где `sampleRate`
   прочитан из заголовка.
6. Везде, где результат вычисления может выйти за `int16`, требуется насыщение (clamp) к [-32768, 32767].
   Промежуточные вычисления вести в `int32_t` или `double` - переполнение знакового `int16_t`
   это UB, а не "обрежется само".

### Технические требования

Архитектура и модули:

- Работа с WAV (чтение/запись) и конвертеры — полностью независимые модули.
- "Фабричный метод" для создания конвертеров:
  - Регистрация конвертера по имени, описание, сигнатура параметров, фабрика экземпляров.
  - Набор зарегистрированных конвертеров используется для парсинга конфигурации и генерации справки (-h).
- Разбор конфигурационного файла — отдельный класс (парсер), возвращающий валидированную последовательность операций с типизированными аргументами.
- Исполнитель (pipeline) связывает WAV I/O и конвертеры.

Производительность и память:

- Память не должна зависеть от длины потоков. Требование проверяемое: пиковое потребление
  на файле 10 минут и на файле 10 секунд должно отличаться незначительно. Замер приложить в `REPORT.md`.
- Обработка должна быть потоковой (chunk-based): фиксированный буфер, последовательное чтение/запись.
  Чтение всего файла в `std::vector<int16_t>` - невыполнение этого требования, даже если работает.
- Для конвертеров, требующих дополнительный поток, читать вторичный поток независимо, синхронизируя по смещению.
- Ограничение на память - главное архитектурное ограничение задачи. Оно определяет интерфейс конвертера:
  конвертер обязан уметь отдавать выходной блок, увидев ограниченное окно входа. Спроектируйте интерфейс
  до того, как писать конвертеры, иначе переделывать придётся всё.

Поддержка форматов и ошибки:

- При неподдерживаемом формате входного файла — корректное сообщение и завершение с соответствующим кодом.
- Использовать исключения C++ для ошибок. Рекомендуемая иерархия:
  - SoundProcessorError (базовое)
    - CmdlineError
    - IoError
    - UnsupportedFormatError
    - ConfigError
    - ProcessingError
- Программа выводит сообщение об ошибке в std::cerr и завершает работу с ненулевым кодом.

Рекомендуемое отображение кодов возврата:

- 0 — успех
- 1 — ошибка аргументов командной строки
- 2 — ошибка ввода/вывода (открытие/чтение/запись)
- 3 — неподдерживаемый формат входного файла
- 4 — ошибка в файле конфигурации (парсинг/валидация)
- 5 — ошибка обработки (во время конвертации)

Справка (-h/--help):

- Должна содержать:
  - Строку использования (usage) и примеры запуска.
  - Описание поддерживаемых форматов WAV.
  - Перечень конвертеров, для каждого: имя, смысл, параметров, синтаксис.
  - Пояснение про ссылки $n и единицы измерения (секунды).
- Содержимое формируется динамически из зарегистрированных конвертеров.

Тестирование:

- Использовать Google Test Framework (подключён в шаблоне CMake).
- Обязательно:
  - Тесты парсера конфигурации (валидные/ошибочные кейсы).
  - Тесты конвертеров на коротких синтетических буферах (mute, mix, ваш конвертер): значения и граничные случаи (смещения, края интервалов, клэмпинг).
  - Тесты WAV I/O (минимальный корректный заголовок, корректность размеров, round-trip на коротком буфере).
- При невозможности слуховой проверки использовать визуальные проверки в редакторе (Audacity).

Сборка:

- Проект собирается шаблоном курса: https://github.com/haiodo/oop-cpp-template
- Тесты включены в сборку; добавьте собственные тест-кейсы.

### При сдаче задания продемонстрировать

`-Wconversion` в этой задаче срабатывает постоянно: `double` в `int16_t`, `size_t` в `int`.

### Зачёт

Работа с WAV:

- [ ] Файл разбирается как последовательность чанков RIFF, а не как 44 байта заголовка.
- [ ] Посторонние чанки (`LIST`, `fact`, `JUNK`) пропускаются по размеру.
- [ ] Учтён байт выравнивания после чанка нечётного размера.
- [ ] Размер данных берётся из заголовка чанка `data`.
- [ ] `sampleRate` и `bitsPerSample` читаются из `fmt `, а не подставляются константами.
- [ ] Работает на файле, сконвертированном ffmpeg **без** ключа `-bitexact`.
- [ ] Выходной файл корректен: правильные размеры, открывается в Audacity.

Конвертеры:

- [ ] `mute`, `mix` и третий конвертер реализованы и дают слышимый эффект.
- [ ] Промежуточные вычисления не переполняют `int16_t`; где нужно - ограничение диапазона.
- [ ] Правило округления в `mix` зафиксировано и проверено тестом на отрицательных значениях.
- [ ] Третий конвертер потоковый: не требует держать весь сигнал в памяти.

Архитектура:

- [ ] Работа с WAV и конвертеры - независимые модули.
- [ ] Конвертеры регистрируются по имени; справка `-h` строится из реестра,
      а не написана текстом.
- [ ] Разбор конфигурации - отдельный класс, возвращающий проверенную последовательность
      операций с типизированными аргументами.
- [ ] Память не зависит от длины входа: замер на 10 секундах и 10 минутах приложен.
- [ ] Иерархия исключений; сообщения в `stderr`; коды возврата 0-5 как описано.
- [ ] Пустой конфиг даёт копию входного файла, а не ошибку.

Ошибки (проверяются на приёме, каждый непройденный случай - незачёт):

Тесты:

### Автомат

Дополнительно к зачёту, не менее трёх пунктов:

- [ ] **Конфигурация проверяется целиком до начала обработки.** Ошибка в последней строке
      конфига из 10000 команд обнаруживается **до того**, как прочитан первый семпл.
      Проверяется так: берётся конфиг на 10000 корректных команд, в последнюю строку вносится
      ошибка (неизвестный конвертер, `mix $99`, лишний аргумент). Программа обязана:
      - сообщить об ошибке с номером строки и завершиться с кодом 4;
      - **не создать** выходной файл вообще, а если он уже существовал - не изменить его.

      Смысл требования: недопустимо потратить минуты на обработку и умереть на последней
      команде, оставив на диске обрезанный WAV, который выглядит как готовый результат.
      Разбор и проверка конфигурации - отдельный этап, полностью предшествующий обработке.

- [ ] **Конфигурация на 10000 команд отрабатывает.** Не переполняется стек (цепочка
      конвертеров не должна быть рекурсивной), потребление памяти не растёт линейно
      от числа конвертеров сверх буферов самих конвертеров. Замер времени и памяти
      в `REPORT.md` рядом с замером на конфиге из 3 команд.

- [ ] Поддержка стерео: конвертеры работают поканально.
- [ ] Поддержка произвольной частоты дискретизации и 8/24/32 бит на семпл.
- [ ] Конвертер с ограниченной линией задержки (echo, reverb) с указанием
      требуемой памяти в `REPORT.md`.
- [ ] Ключ `--dry-run`: проверить конфигурацию и вывести план обработки, ничего не записывая.
- [ ] Именованные параметры в конфигурации (`mute start=0 end=30`) наравне с позиционными.
- [ ] Свои конвертеры сверх обязательных трёх, с описанием в справке.

### Разговор: живая модификация

Одна на выбор преподавателя. При правильной архитектуре новый конвертер - это один класс
и одна строка регистрации, справка обновляется сама. Если потребовались правки в работе
с WAV, в исполнителе или в коде справки - модули не были независимы.

1. `fadein start end` - линейное нарастание громкости от 0 до 1 на интервале.
2. `reverse_polarity` - `y[i] = -x[i]`, аккуратно со значением `-32768`.
3. `mix $n offset weight` - взвешенное смешивание.
4. Поддержка 48000 Гц наравне с 44100, времена по-прежнему в секундах.
5. `crop start end` - оставить только указанный интервал, длина выхода меняется.
6. Ключ `--dry-run`.
7. Сделать так, чтобы об **всех** ошибках конфигурации сообщалось за один проход,
   а не только о первой найденной.

### Артефакты в REPORT.md

- Полный вывод `-h`.
- Скриншоты из Audacity: форма волны до и после для **каждого** конвертера.
  Для `mute` должна быть видна тишина ровно на заданном интервале, с отсчётами по времени.
- Пиковая память на входе 10 секунд и 10 минут, два числа рядом
  (`/usr/bin/time -l` на macOS, `/usr/bin/time -v` на Linux).
- Подтверждение работы на файле из ffmpeg без `-bitexact`.
